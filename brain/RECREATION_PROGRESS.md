# 44-sample bespoke recreation tracker

Method (per user correction, session N): each reference is recreated ONE AT A TIME as a
bespoke, non-archetype build directly from engine/core.py + engine/build.py + engine/doodles.py
+ engine/layout.py primitives. NOT routed through engine.py's ARCHETYPES registry, NOT pulled
from a rotating content bank. Each is its own composition, in AQ's brand language, inspired by
(not copying) the reference's structural read. Every gap found between recreation and reference
is checked for whether it reveals a MISSING GENERALIZED DECISION LAYER (goes in engine/layout.py
or brain/DECISIONS.md) vs a one-off scripting bug (fixed locally, not generalized).

## Rule for every loop iteration
1. Pick the first `pending` or `in_progress` row.
2. View the reference jpg. Note its structural read (framing device, focal mechanism, layering) in 1-2 sentences.
3. Build a bespoke script in the scratchpad importing engine/core.py, build.py, doodles.py, layout.py directly (list of html strings via `B.page`/`B.render`). Do NOT use engine.py's ARCHETYPES/generate(). Vary the underlying composition mechanism deliberately from prior samples (don't reuse the exact same skeleton every time — that recreates the "same 4-5 archetypes" complaint at one remove).
4. Render, view visually, run engine/ref_metrics.analyze() on both ref and output, compare.
5. If a gap reveals a genuinely reusable decision (like the quadrant-fill / overlap-scoping fix), encode it in engine/layout.py or brain/DECISIONS.md — never hand-patch just the one output file.
6. Mark the row done (or in_progress with a one-line note) and move to the next row.
7. Keep per-iteration scope small — one sample fully handled (or one meaningful revision) per loop firing, not all 44 in one shot.
